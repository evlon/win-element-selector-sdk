## 1. 概述

本文档定义捕获与定位系统的需求规格，重点在于 **一次定位** 和 **二次定位** 的设计。系统旨在为 UI 自动化提供**确定、高速、可诊断**的元素定位能力。核心原则：**所有定位策略必须在开发阶段（捕获/校验时）确定，生产运行阶段不得有自动 fallback 或隐式策略切换**。

---

## 2. 核心原则

| 原则 | 说明 |
|------|------|
| **速度优先** | 优先使用基于 `AutomationId` 的 `FindFirst`；路径每一级尽可能高效。 |
| **唯一性仅对 findOne 的叶子节点强制** | `findOne` 仅要求叶子节点在父节点下唯一；中间节点使用 `FindFirst` 返回第一个匹配，不验证唯一性。`findFirst` 和 `findAll` 完全不要求唯一性。 |
| **无自动 fallback** | 定位参数（`LocateMode`/`SearchStrategy`）必须显式指定，不允许运行时推断或降级。 |
| **利用 UIA 原生能力** | 后代查找使用 `TreeScope.Descendants`；直接子查找使用 `TreeScope.Children`。 |
| **性能可预测** | 提供典型场景的耗时估算，避免客户端低效递归。 |

---

## 3. 术语定义

| 术语 | 定义 |
|------|------|
| **一次定位** | 从窗口根开始，根据绝对 XPath 查找元素。 |
| **二次定位** | 从已知父元素（通过 RuntimeId 获取）开始，在其子树中根据相对 XPath 查找元素。 |
| **捕获** | 根据屏幕坐标生成选择器（XPath）和搜索上下文，供后续定位使用。 |
| **校验** | 验证选择器在当前窗口状态下是否仍能匹配，并返回详细失败原因（开发阶段使用）。 |
| **LocateMode** | 指定一次定位的遍历策略：`Fast`（ControlView）或 `Full`（RawView）。 |
| **SearchStrategy** | 指定二次定位的遍历策略：`Fast` 或 `Full`。 |
| **FilterCondition** | 对 `findAll` 结果的附加过滤条件，基于元素属性。 |
| **RuntimeId** | UIA 元素的运行时唯一标识符，用于从缓存快速获取 `IUIAutomationElement`。 |

---

## 4. 捕获（Capture）需求

捕获用于**开发阶段**生成稳定的定位器。其输出（XPath + SearchContext）供生产定位使用。

### 4.1 捕获模式

| 模式 | 用户选择 | Walker | BFS 深度 | 适用场景 |
|------|---------|--------|----------|----------|
| **Normal** | 是 | ControlView | 5 层 | 原生应用，快速生成轻量选择器 |
| **Enhanced** | 是 | RawView | 30 层 | 嵌入式 Web 视图、复杂框架 |

### 4.2 捕获输出

```rust
pub struct CaptureResult {
    pub xpath: String,                  // 生成的绝对 XPath
    pub locate_mode: LocateMode,        // Fast 或 Full（是否 Child 由 search_root 表达）
    pub search_context: SearchContext,  // 定位所需上下文（含起点、子HWND提示）
    pub hierarchy: Vec<HierarchyNode>,  // 层级链（调试用）
    pub error: Option<String>,
}
```

### 4.3 跨进程处理

- 捕获时自动检测目标元素是否跨进程（PID 与顶层窗口不同）。
- 若跨进程，记录命中的子 HWND 信息（`class` + `title`）到 `SearchContext.child_hwnd_hint`，并设置 `search_root = ChildHwnd { class, title }`。

## 5. 一次定位（Locate）需求

一次定位从**窗口根**开始，根据绝对 XPath 查找元素。

### 5.1 公共参数

所有一次定位 API 必须接收：

- `window_selector: String` —— 窗口标识（句柄、类名+标题、进程名等）
- `xpath: String` —— 绝对 XPath（以 `/` 开头）
- `locate_mode: LocateMode` —— 必须显式指定，无默认值

### 5.2 XPath 语法与语义

| 表达式 | 含义 | 搜索范围 | 实现策略 |
|--------|------|----------|----------|
| `/A` | 当前节点的直接子元素中名为 A 的元素 | Children | `FindFirst(TreeScope.Children, Condition)` |
| `//A` | 当前节点的所有后代元素中名为 A 的元素（不限层数） | Descendants | `FindFirst(TreeScope.Descendants, Condition)` |
| `/*/A` | 当前节点的孙子元素（深度 2）中名为 A 的元素 | BFS 深度 2 | 手动递归 Children，限制深度 2 |
| `/*2/A` | 当前节点的曾孙元素（深度 3）中名为 A 的元素 | BFS 深度 3 | 手动递归 Children，限制深度 3 |

> `/*n/` 表示经过 n 层任意节点（深度 n+1）。数字 n 必须 ≥1。若 n 省略（即 `/*/`），默认深度 2。

### 5.3 三种定位语义

| API | 行为 | 中间节点唯一性 | 叶子节点唯一性 | FilterCondition |
|-----|------|---------------|---------------|-----------------|
| `findFirst` | 返回第一个匹配元素 | ❌ 不要求 | ❌ 不要求 | ❌ |
| `findOne` | 返回唯一匹配元素，否则报错 | ❌ 不要求（同 `findFirst`） | ✅ **必须唯一** | ❌ |
| `findAll` | 返回所有匹配元素 | ❌ 不要求 | ❌ 不要求 | ✅ |

#### 5.3.1 `findOne` 唯一性验证细节

- **路径上的每一级（非叶子）**：使用 `FindFirst` 返回第一个匹配，不检查是否有第二个。
- **叶子节点**：定位后必须验证同一父节点（或同一祖先范围内，若叶子使用 `//`）下**不存在另一个**满足相同条件的元素。实现方式：使用 `FindAll` 限制返回 2 个元素，若 count > 1 则报错 `LeafNotUnique`。

#### 5.3.2 示例

XPath: `/pane[@AutomationId='Nav']/button[@AutomationId='Submit']`

- 第一步：在根下找 `pane[@AutomationId='Nav']`，调用 `FindFirst`，取第一个（即使存在多个同 ID 的 pane）。
- 第二步：在该 pane 下找 `button[@AutomationId='Submit']`，同样调用 `FindFirst`，然后立即检查该 pane 下是否还有第二个同 ID 的 button。若有，报错 `LeafNotUnique`。

### 5.4 执行策略与 TreeScope 选择

解析 XPath 每个 step 时，根据语法决定 `TreeScope` 和算法：

| Step 语法 | TreeScope | 算法 | 说明 |
|-----------|-----------|------|------|
| `/A` | Children | `FindFirst` | 直接子，最快 |
| `//A` | Descendants | `FindFirst` | 全树后代，UIA 原生 |
| `/*/A` | Children + 递归 | BFS 深度 2 | 手动递归，限制深度 2 |
| `/*2/A` | Children + 递归 | BFS 深度 3 | 手动递归，限制深度 3 |
| `/*n/A` (n>2) | Children + 递归 | BFS 深度 n+1 | 手动递归，需超时保护 |

> **禁止**对 `/*n/` 使用 `Descendants` 后再过滤深度；必须手动逐层 `Children` 遍历并限制深度。

### 5.5 超时与重试

- 超时预算可配置：`Fast` 默认 1500ms，`Full` 默认 3000ms。
- 不允许自动重试。超时后必须返回 `Timeout` 错误。

## 6. 二次定位（LocateFrom）需求

二次定位从**已知父元素**（通过 RuntimeId 获取）开始，在其子树中根据**相对 XPath** 查找元素。

### 6.1 公共参数

所有二次定位 API 必须接收：

- `parent_runtime_id: String` —— 父元素的 RuntimeId（必须从缓存可解析为 `UIElement`）
- `relative_xpath: String` —— 相对 XPath（不以 `/` 开头），例如 `button[@AutomationId='Ok']` 或 `/*/listitem`
- `strategy: SearchStrategy` —— `Fast` 或 `Full`，必须显式指定

### 6.2 三种定位语义

| API | 唯一性要求 | FilterCondition |
|-----|-----------|-----------------|
| `findFirstFrom` | 不要求 | ❌ |
| `findOneFrom` | 叶子节点唯一（中间节点同 `findFirst`） | ❌ |
| `findAllFrom` | 不要求 | ✅ |

执行策略与一次定位完全相同，仅起点为父元素。

### 6.3 父元素有效性

- 调用方必须保证 `parent_runtime_id` 对应的元素仍然存在（系统不自动刷新缓存）。
- 若无效，返回 `InvalidParent` 错误。

## 7. 校验（Validate）需求

校验用于开发阶段诊断定位失败原因。其输入与一次定位相同，输出详细的失败诊断。

### 7.1 接口

```rust
pub struct ValidateRequest {
    pub window_selector: String,
    pub xpath: String,
    pub locate_mode: LocateMode,
}

pub struct ValidateResponse {
    pub valid: bool,
    pub failed_step: Option<usize>,      // 第几步失败（从0开始）
    pub reason: NotFoundReason,          // 失败原因枚举
    pub suggestions: Vec<String>,        // 修复建议
}
```

### 7.2 失败原因枚举

```rust
pub enum NotFoundReason {
    WindowNotFound,
    ChildHwndNotFound { class: String, title: String },
    StepNotFound { step: usize, xpath: String },
    LeafNotUnique { candidates: usize },   // findOne 叶子节点有多个匹配
    Timeout { budget_ms: u64, elapsed_ms: u64 },
}
```

> 注意：`StepNotUnique` 已移除，因为中间节点不要求唯一性。

### 7.3 使用场景

- 捕获后立即校验，确保生成的选择器有效（特别是 `findOne` 的叶子唯一性）。
- 自动化脚本编写时，手动调用校验 API 验证定位表达式。
- 生产环境**不应**调用校验 API。

```rust
    pub class: String,
    pub title: String,

```

### 8.3 SearchStrategy（用于二次定位）

```rust
pub enum SearchStrategy {
    Fast,   // ControlViewWalker
    Full,   // RawViewWalker
}
```

### 8.4 FilterCondition（仅用于 findAll / findAllFrom）

```rust
pub struct FilterCondition {
    pub property: String,      // 属性名，如 "Name", "ControlType"
    pub operator: FilterOp,
    pub value: String,
}

pub enum FilterOp {
    Eq,        // 等于（可尝试 UIA 原生）
    NotEq,     // 不等于（客户端过滤）
    Contains,  // 包含（客户端过滤）
    Regex,     // 正则（客户端过滤）
    Exists,    // 属性存在（客户端过滤）
}
```

> 性能提示：非 `Eq` 操作无法使用 UIA 原生条件，必须在 `FindAll` 后客户端过滤。

```rust
    WindowNotFound,

    StepNotFound(usize),
    LeafNotUnique,
    FilterMismatch,
    Timeout,
}
```

## 9. 性能约束与优化建议

### 9.1 典型耗时

| 操作 | 预期耗时 | 说明 |
|------|----------|------|
| 单个 PropertyCondition 构建 | 10–50 μs | 忽略不计 |
| `FindFirst` 使用 `Children` 范围（<100 子元素） | 0.1–0.5 ms | 推荐用于固定层级 |
| `FindFirst` 使用 `Descendants` 范围（5000 节点） | 5–15 ms | 仅适用于 `//` 后代查找 |
| 手动 BFS 深度 2（分支因子 50） | 1–2 ms | 取决于子元素数量 |
| 手动 BFS 深度 3（分支因子 50） | 10–20 ms | 可能较慢，谨慎使用 |
| `findAll` 返回 100 个元素并过滤 | ≤ 300 ms | 需配合 BuildCache |
| `findOne` 叶子唯一性验证（多取一个元素） | 额外 0.1–0.5 ms | 可接受 |

### 9.2 优化策略表

| 场景 | 推荐做法 | 禁止做法 |
|------|----------|----------|
| 固定层级路径 `/A/B/C` | 逐级 `Children` + `FindFirst` | 使用 `Descendants` 或客户端递归 |
| 后代查找 `//button` | 直接 `FindFirst(TreeScope.Descendants, condition)` | 手动递归遍历所有子孙 |
| 深度限制（如 `/*2/button`） | 手动 BFS 逐层 `Children` 并限制深度 | 使用 `Descendants` 后过滤深度 |
| `findAll` 结果过滤 | 先 `FindAll` 获取元素列表，再客户端过滤 | 在 `FindAll` 前使用复杂条件（无法索引） |
| 属性条件非“等于” | 先用简单条件缩小范围，再客户端二次过滤 | 直接对全树应用 `NotCondition` 或通配符 |

### 9.3 BuildCache 使用

参照原始文档 5.3 节，在以下场景使用 BuildCache：
- 捕获时层级链构建（8–10 属性 × 5–15 元素）
- 捕获时 BFS 深搜（4 属性 × 20–50 子元素）
- 校验时属性比对（5–8 属性）

二次定位不使用 BuildCache（因为缓存直接获取 UIElement，无跨进程调用）。

## 10. 开发阶段 vs 生产阶段职责划分

| 阶段 | 允许的操作 | 禁止的操作 |
|------|-----------|-----------|
| **开发/测试** | 捕获、校验、修改定位参数、调整 XPath | 在生产环境执行校验 |
| **生产运行** | 使用固化的 `SearchContext` + XPath 调用 `findFirst`/`findOne`/`findAll` | 动态推断 `LocateMode`、自动 fallback、调用校验 API |

> **固化方式**：将捕获结果（XPath + SearchContext）序列化为配置文件或代码常量，生产时直接反序列化使用。

## 12. 实现指南

### 12.1 findOne 叶子唯一性验证实现

```rust
fn find_one_leaf(parent: &UIElement, leaf_step: &XPathStep, walker: &Walker) -> Result<UIElement> {
    let scope = if leaf_step.is_descendant { TreeScope::Descendants } else { TreeScope::Children };
    let condition = build_condition(leaf_step);
    // 最多取 2 个，验证唯一性
    let matches = parent.find_all(scope, condition, walker, 2);
    match matches.len() {
        0 => Err(LocateError::StepNotFound(last_step_index)),
        1 => Ok(matches[0].clone()),
        _ => Err(LocateError::LeafNotUnique),
    }
}
```

### 12.2 深度限制 BFS 实现

```rust
fn find_with_depth_limit(
    root: &UIElement,
    target_step: &XPathStep,
    max_depth: u32,
    walker: &Walker,
) -> Vec<UIElement> {
    let mut results = vec![];
    let mut queue = vec![(root.clone(), 0)];
    while let Some((node, depth)) = queue.pop() {
        if depth == max_depth {
            let children = node.find_all(TreeScope::Children, target_step.condition, walker);
            results.extend(children);
        } else if depth < max_depth {
            let children = node.find_all(TreeScope::Children, Condition::True, walker);
            for child in children {
                queue.push((child, depth + 1));
            }
        }
    }
    results
}
```

### 12.3 XPath 解析与深度提取

正则匹配 step：`^(//?|\*(\d+)?/)([^\[\]]+)(\[.*\])?$`

- 若以 `//` 开头 → `is_descendant = true`, `max_depth = None`
- 若以 `/*` 开头 → 提取数字 n（默认 1），`max_depth = n + 1`, 需要 BFS
- 若以 `/` 开头 → `is_descendant = false`, `max_depth = None`

### 12.4 RuntimeId 缓存

使用 LRU 缓存，最大容量 500。缓存 key 为 RuntimeId 字符串，value 为 `UIElement`（或弱引用）。元素销毁时由调用方负责从缓存移除（或允许缓存失效后报错）。

## 13. 对现有实现的修改指引

1. **移除所有隐式 fallback**：删除 `Adaptive` 策略、删除通过 XPath 前缀推断模式的代码。
2. **实现 XPath 深度限制语法**：解析 `/*n/` 并实现对应的 BFS 遍历。
3. **findOne 仅叶子唯一性验证**：路径中间节点使用 `FindFirst` 不验证，最后一步增加唯一性检查。
4. **为二次定位增加 RuntimeId 缓存**：LRU 缓存，容量 500。
5. **为 findAll 增加 FilterCondition**：支持 Eq/NotEq/Contains/Regex/Exists，非 Eq 操作客户端过滤。
6. **超时预算按模式可配置**：Fast 默认 1500ms，Full 默认 3000ms。
7. **校验 API 返回详细失败原因**：包含失败步骤、叶子不唯一等诊断信息。

## 14. 总结

本需求规格定义了以**速度优先、唯一性仅限 findOne 叶子节点**为核心的捕获与定位系统。通过明确的 XPath 语法（`/`、`//`、`/*n/`）和对应的执行策略（Children、Descendants、深度限制 BFS），开发人员可以在开发阶段固化定位参数，生产阶段获得确定、高速的定位能力。`findFirst` 提供最快速度，`findOne` 提供叶子唯一性保证，`findAll` 支持结果过滤。二次定位基于 RuntimeId 进一步消除父元素搜索开销。所有策略均无自动 fallback，确保行为可预测、性能可度量。
